## 实际交互变化

- 同一合同输入框完成本地号码遮蔽和人工检查；“已检查隐私，开始分析”确认当前全文。粘贴即时处理、普通输入空闲500ms处理，组合输入结束后处理。提交时若发现新的号码先更新文字，要求再次点击，不直接上传未经确认的新文字。
- 合同原文保持在统一工作区。宽屏为风险导航／完整合同／当前任务；无结果时不强撑空导航。窄屏、矮窗和放大时自然重排。长合同定位到中部时，仅完整放得进视口的辅助面板跟随阅读，不裁切长内容。
- 右栏分别显示问题说明、写沟通消息、练习结果与清单。核心“准备沟通”在说明顶部。顶部稳定保留“检查合同／常见场景练习”。固定模拟房东明确称条件确认练习；AI起草是独立可选能力。
- 修改目标保留旧草稿与待补问题，明确标为“修改前的参考草稿”。新请求失败仍保留参考；采用旧稿必须主动点击，覆盖已有消息需确认，之后需重新确认消息隐私。
- A→B→A 恢复消息与确认；场景独立，独立练习也使用相同记录结构。另开一次练习使用新会话，旧会话可从记录选择器恢复；未知提交结果时禁止另开。
- 编辑分析中的合同是编辑下一版；在途请求保留提交文本。新分析生成本地随机版本，和后端有时效的 review_context_id 分开。旧结果、旧练习不清空，重复 C-01 不串记录。
- 导出固定到点击时的具体模拟会话，不跨场景合并。迟到的剪贴板失败只保留原会话的回退文本，不抢另一条款输入焦点；复制反馈直接出现在结果页。
- 处理详情按所属请求筛选，与法律依据分开；不拼接不同任务的 Trace，不伪造等待节点。

## 复现命令

在仓库根目录 PowerShell 执行；输出目录必须是本轮新建且不存在的目录，避免覆盖。

```powershell
$env:PYTHONUTF8='1'
$env:PYTHONIOENCODING='utf-8'
.\.venv\Scripts\python.exe -m pytest --basetemp=.runtime/ux-v4/pytest-release-temp -o cache_dir=.runtime/ux-v4/pytest-release-cache -o faulthandler_timeout=40
node scripts/check_day08_frontend.cjs --out .runtime/ux-v4/release-day8 --runtime-dir .runtime/ux-v4/release-day8-browser
node scripts/check_day10_frontend.cjs --out .runtime/ux-v4/release-day10 --runtime-dir .runtime/ux-v4/release-day10-browser
node scripts/check_layout_visual.cjs --out .runtime/ux-v4/release-visual --runtime-dir .runtime/ux-v4/release-visual-browser
```

再次运行请替换目录后缀。`--basetemp` 只用一次性测试目录，不能指向证据目录。受限沙箱无法创建本机测试连接时，本次在获准的本机执行环境运行；没有禁用网络或会话安全断言。

中途修复了：旧健康测试需要的真实开发者文档入口（收进页脚折叠区）；Windows父子进程UTF-8/GBK不一致；新浏览器测试的字符串转义与Vue更新时序模拟；长合同定位时右侧说明滚出屏幕；发送前二次遮蔽需要显式撤销所属记录的隐私确认；复制反馈被放在隐藏的消息面板。最终结果以上表为准，不以试跑失败输出冒充通过。

- 记录只在当前页面内存中保留，刷新／关闭仍会丢失；界面和README有提示。本轮未新增长期存储。
