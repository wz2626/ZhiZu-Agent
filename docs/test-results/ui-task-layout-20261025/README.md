## 本次修正的结构问题

原实现的卷宗和560px协商卡各占完整一行，协商卡右对齐，导致居中卷宗下面出现孤立右卡和巨大左下空洞。本次从展示结构上移除该组合：

- `screen=intake`：只显示居中合同输入／脱敏预览卡，标题、步骤、操作区统一阅读轴。主按钮回到卡片正常底部，隐私文字不被悬浮药丸遮挡。
- `screen=review`：展开合同正文和审阅结果；演练区域仍挂载但不显示、不占空间、不可聚焦。
- `screen=arena`：显式进入独立协商工作区；左侧是条款、相邻上下文和具体建议，右侧是分数、场景、回应、已确认条件和唯一消息输入框。
- Trace 为正常流中真正占位的页面底部区域，无记录时弱化，有记录可从顶部入口定位查看。不再以 fixed 浮层和160/620px尾部空白补偿遮挡。

`screen` 是 `workspaceMode + phase` 的派生展示状态，不是后端业务阶段。输入框使用 `v-show + inert` 保持同一个DOM实例；返回卷宗保留草稿、隐私确认、轮次、分数与正式条件，并退出Tab序列。

## 批注密度与精确锚点

- 同一原文段落的结果归组。默认显示紧凑摘要或组内按钮，只有当前选中的结果展开完整解释、证据与建议。
- 一般长合同保留SVG页边轨道，按组在12px网格避让；组内每个条款单独计算原句字形坐标和对应按钮位置，不复制代表连线。无精确原句的结果不画推测连线。
- 短而密集的合同使用逐段就地批注：至少4项结果且平均每项对应原文不足100字时启用。避免几行合同旁边的长解释撑出整片左侧空白；原文、全部结果、解释和证据均保留。
- 就地批注紧随原句，因此展开说明不重复再引用同一句。空行仍保留在原文快照及DOM文本中，仅减少这种密集布局中的视觉行距。
- 长解释区域有最大阅读高度，可通过键盘和滚动完整查看；没有截断或删除响应内容。

- 1440×900 输入页：整页高度900px；编辑卡宽920px，主按钮底边约760.33px，进入页面无需滚动即可看到主操作。

- Trace 按真实内容占位，不覆盖发送、隐私确认或手动复制文本框。全部测量见视觉JSON，首屏发送按钮检查在任何 `scrollIntoView` 之前完成。

## 视觉迭代中实际发现并修复的问题

1. Vue挂载容器本身的动态属性未被编译，导致任务类名不生效。增加外层挂载容器，使内部 `#app` 的派生界面属性真实渲染。
2. 审阅页标题收缩，未与卷宗同轴。统一宽度和对齐。
3. 主舞台重复展示左侧已有的建议，把输入推到首屏外。建议集中到左侧，并将限制说明移至实际输入操作区。
4. 短合同配长批注仍有大块侧轴空白。增加密集材料逐段布局，并收紧空行／批注间距、删除就地详情中的重复引文；保留1200px检查，没有用提高门槛绕过失败。
5. 失败原因可能位于首屏下方。舞台标题处增加真实状态入口，用户可以主动定位完整原因；异步结果不自动抢焦点。
