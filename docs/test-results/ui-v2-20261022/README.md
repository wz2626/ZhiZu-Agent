## 交付行为

- `phase` 保留业务含义，`workspaceMode` 独立控制卷宗和对弈桌；视图切换不发请求、不重置草稿、隐私确认、会话和正式结果。
- 从固定脱敏快照生成全部精确原句区间。重复、嵌套、自重叠、跨段命中都保留；原文通过插值渲染，无法定位时明确提示。
- 宽屏批注以实际字形坐标锚定，并沿 12px 网格避让；引线默认透明度 0.08，hover/激活时 0.75。窄屏将同一批注排到相关段落下方，左边保留 2px 色条。
- 双向选择原句和批注；不相关正文透明度为 0.3；Esc/退出聚焦恢复。进入演练保留已选择的重复出现位置。
- Composer 只有一个 DOM 实例。迁移使用 260ms CSS transform，减少动态效果时关闭过渡。保留消息重扫、隐私门禁和 Ctrl/Cmd+Enter；首轮空分数仍为“不可评分”。
- 对弈桌采用上下文/主舞台结构，主舞台上方展示正式回应及条件，下方展示输入区。底部控制台只回放 `activeTrace`，等待阶段只有提交与计时提示，无占位节点；retry 维持琥珀色。
- 渐变描边、品牌焦点晕影、代码字体、分析骨架及一次性回应呼吸边框继续保留。没有打字机或伪流式输出。

## 空间与降级实测

| 环境 | 布局 | 测量与行为 |
| --- | --- | --- |
| 1440×1080 卷宗 | wide | 卷宗宽 1361px；页边线程宽 560px |
| 1440×1080 对弈桌 | wide | 上下文宽 374.36px，主舞台宽 962.64px，接近 28% / 72% |
| 输入框高度代理 520px | wide，自然纵向撑开 | Composer 高 694.80px；发送按钮仍可滚动到完整可用区域，DOM、草稿及确认保留 |
| 1440×560 | flow | 上下文和主舞台各宽 1361px，顺序堆叠 |
| 1440×700/800/900/920/1080 | wide | 回应、条件及发送按钮均能完整进入控制台上方可用区域 |
| 200% CSS 布局放大 | flow | 工作区布局宽 649 CSS px；无页面横向溢出，操作可达 |
| 390×844 | flow | 两区各宽 362px；行内批注/消息/清单可用，无页面横向溢出 |

V2 已替换三栏专用 R2.1 固定区实现和旧像素断言；保留空间不足时降级、状态不随几何改变、错误和隐私说明完整可达的原则。当前宽屏条件为工作区布局宽至少 960px 且视口高至少 680px；其余采用 flow，输入区始终随文档自然撑开，避免旧固定高度正文被挤压的问题。

放大使用 `document.body.style.zoom = '2'`，是可复现的布局重排代理，不声称浏览器“仅文字放大”；输入框高度使用 `style.height='520px'`，是几何代理，不声称实体鼠标拖动。浏览器截图过程会产生临时视口诊断，验收以 JSON 中带 label 的稳定 `layoutMeasurements` 为准。

控件可达验收同时检查完整边界、`elementFromPoint` 命中和真实 CDP 键盘操作。Trace 详情支持键盘展开、查看最后一项、Esc 关闭；焦点离开非模态控制台时自动收起。等待态既不渲染新节点，也不把此前记录冒充当前进度。
