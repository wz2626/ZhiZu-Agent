状态：Day 7，2026-10-11 经开发者授权新增。继承 Spec 00 的会话隔离、5 轮上限和最多 2 次重写约定；本模块不修改合同审查引擎。

2026-10-14：经开发者明确授权，三场景模板/规则、HTTP入口、失败缓存与真实Trace扩展见 [Spec 04](spec-04-negotiation-api-and-scenarios.md)。本文公式不变；旧Python服务保留失败可再执行的兼容行为，HTTP缓存失败响应并要求新编号才能重新执行。

## 1. 规则配置与算分

服务持有可信规则配置，模型只能提取候选值，不能修改起点、目标、权重或底线。每项含 `start`、`target`、`weight`、`applicable` 和可选闭区间 `minimum/maximum`。默认演示项 `deposit_refund`：起点 0、目标 2000、权重 1、允许确认值 0～2000；该区间仅为演练配置，不是法律结论。

仅对已确认状态中存在、标记适用、目标不等于起点且权重为有限正数的规则求和。缺失项、不适用项、无效权重项不进入分母。目标等于起点视为不适用项，排除权重，不判满分；无适用项返回 `None`（不可评分），不伪造零分。

单项 `p = clip((confirmed - start) / (target - start), 0, 1)`，分数 `round(100 * p)`。支持目标低于起点。多项 `round(100 * Σ(w_i * p_i) / Σw_i)`，先合并原始进度再统一舍入；采用 Python `round` 的半偶舍入，使用有理数避免浮点累计误差和权重溢出。值和边界必须为有限数值，布尔值不能充当金额。

分数从完整确认状态重算，与请求数、轮次、引用法条数和重试次数无关。押金确认 1000 得 50，1500 得 75；同一金额重复确认保持同分。展示标签为“模拟协商进展分”。

## 2. 房东提取与 Critic

默认房东继续明确表示未确认条件，不从租客输入复制金额。可注入离线房东响应器；本轮确定性语义适配器仅接受完整模板 `【模拟房东】我确认返还押金1000元。`，可在其后附 `依据LAW-709、LAW-710。`。条件句、否定、转述、重复或冲突金额均不能当作明确接受。未来模型适配器需要单独验证语义提取能力，本轮不宣称通用自然语言或法律语义质检已经完成。

Critic 检查候选结构、房东确认、数值与回复一致性、有限数值、可信规则及其底线。为兼容 Day 6，非数值安排仅接受原模拟房东的明确安排模板与对应 `arrangement` 列表，此类安排不计分。未知数值项目拒绝，不能绕过配置进入确认状态。

候选 `evidence_ids` 必须无重复，属于 LAW-703～LAW-734，并属于服务提供的 `available_evidence_ids`，且确实出现在房东回复中。该可信集合由调用方提供已检索核验的法条 ID；默认空集合，不把整个法条库自动当成本次检索结果。本轮检查引用身份与来源集合，法条是否实质支持法律结论仍需后续语义复核。确认引用跨轮去重存储；重复引用不参与算分。同一轮重复引用视为候选校验失败。

## 3. 试算与提交

流程为辅导 → 房东候选 → 候选规则试算 → Critic → 通过后提交或有界重写。`candidate_score` 是未提交试算值；既有 `trial_score` 字段在此作为正式当前分数，只有通过 Critic 后才更新。Critic 根据核验后的合并状态重新计算，模型不能覆盖最终分值。

一次通过输出完整的确认条件、确认引用、正式分数、规则解释、历史和新轮次；服务在单会话锁内替换整个快照。Critic 失败或异常保持正式状态原样，至多 3 次生成；内部重试重新提取候选，不累计分数。重复成功 `request_id` 返回缓存快照，不再执行图或推进轮次；相同条款以不同请求确认可以推进有效对话轮次，但分数不增加。
