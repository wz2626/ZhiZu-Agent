# Spec 05：V3 合同绑定反提案草稿

2026-10-25 开发者授权：新增独立、按需生成的协商表达能力。它使用通过审查的上下文帮助组织消息，不改变固定策略房东、计分公式、正式确认条件或五轮上限。离线工程验证与真实模型表达质量分别验收。

## 1. 上下文与输入

详细审查成功时创建 `review_context_id`，绑定不可变的脱敏合同、已通过审查的条款与本次引用的权威法条。服务以有锁、具TTL/容量上限的内存存储保存；标识随机，视为本地应用持有者能力，不作为账号身份验证。重启/过期/淘汰后不能用于新生成请求。验证上下文和条款归属先于任何云客户端初始化，不接受浏览器上传的“已核验”证据。请求获取不可变上下文后不受中途淘汰破坏。

默认上下文30分钟有效、最多100份，容量满时淘汰最久未使用项；每份上下文最多64个独立草稿请求，重复请求不新增记录。失效返回410，新请求条款不归属返回404，同编号内容冲突优先返回409，容量上限返回429并要求重新审查；429不是暂时服务繁忙。

`POST /api/review/proposal` 仅接收严格字段：`review_context_id`、`clause_id`、`goal_text`、`draft_request_id`。标识禁止敏感号码，目标非空且有长度上限；额外字段、非法标识与长度返回受控422，不回显原始输入。客户端请求结构不含谈判提交入口的 `session_id/user_input/request_id` 三字段签名，保留 OpenAPI 唯一发现。

API目标说明为1～2000字，网页输入区上限1000字；生成消息为1～2000字，问题最多8项、每项1～300字。所有文本不能纯空白。模型JSON总长不超过32000字符，重复键、非法常量及深度嵌套安全拒绝。

前端生成前对目标说明做号码遮蔽并展示人工隐私确认；后端在缓存、模型调用和任何公共输出前再次遮蔽。姓名、地址等自由文本仍由用户人工检查。用户说明作为其陈述与目标，不当作房东已确认事实。

## 2. 生成与校验

复用现有聊天模型配置与超时，不新增依赖。上下文提供条款、审查建议与已核验法条；模型只输出 `proposed_message`、`evidence_ids`、`questions`。引用必须属于所选条款的可信证据，不能凭记忆补法条；无证据时只组织诉求/澄清表达并提示依据边界。不得补写个人信息、假造对方已接受条件或给出谈判胜率。

确定性校验检查严格JSON、字段与长度、引用归属和重复、号码脱敏。校验失败最多两次重写、总生成三次；调用异常/超时直接受控失败。格式/引用通过不等于法律语义全面通过；真实质量需另行评估。失败公共响应不含坏草稿、原始异常或任意模型输出。

## 3. 响应与独立幂等

公共响应：三个关联标识 `review_context_id/clause_id/draft_request_id`，`status=success/needs_review`、`proposed_message`、`evidence_ids`、`questions`、`failure_code/reason/errors`、`retry_count`、`trace_label=本次执行回放`、`trace`、`replayed`。失败消息和引用/问题为空，返回受控原因；成功无终止错误。

草稿请求具有独立有界缓存和并发锁。同编号、同上下文/条款/脱敏目标重放相同结果且不再次调用模型；同编号不同内容409。业务失败可缓存；重新生成需新编号。上下文失效和格式拒绝不调用模型。缓存随上下文生命周期/容量受限，不创建长期历史。它不读写谈判正式快照、不消耗协商轮次。

Trace 只记录实际发生的 context/configuration/drafting/critic/retry 等事件，序号连续、耗时实测、反馈受控，不包含上下文ID、目标、草稿、异常或隐藏思维。前端完整响应后回放，来源为“反提案生成”，不与其他请求拼接；等待期间只显示真实等待计时。

## 4. 前端接纳与采用（2026-10-29 统一工作区修订）

目标、参考草稿与待补问题归属本地分析版本+条款。请求额外记录目标修订与生成代次，接纳核对上下文、条款、请求及该记录修订，不依赖当前屏幕选中项。切换条款可接收原条款有效结果；修改目标使旧在途结果失效，但已成功生成的旧稿与问题保留为“修改前的参考草稿”。生成失败不删除旧参考。上下文过期仅阻止新生成，不自动重新分析或发送。

生成入口位于右栏沟通任务内。所有响应只进入预览，不自动填入、发送、滚动或聚焦。用户可明确采用参考草稿；已有消息需要确认替换；采用后撤销当前练习消息的隐私确认。目标确认随目标修订保存，消息确认随练习消息修订保存；单Composer切换记录不算编辑。

草稿不拥有唯一协商session，不修改任何正式练习状态或消耗轮次。传输失败保留原草稿请求编号，目标修改或确定业务失败后的重新生成用新编号。旧响应不能覆盖更新目标，不能污染其他条款。无可用上下文仍可手写消息与进行固定剧本练习。

## 5. 验收

离线测试覆盖有效草稿、空证据、未配置、超时、恶意/格式输出、PII、伪造引用、两次重写成功/三次失败、上下文过期/淘汰/条款归属、并发同编号、冲突和缓存重放。前端验证隐私门禁、已有内容替换确认、迟到响应隔离、单Composer、正式状态/轮次零变化与唯一谈判入口。真实模型效果单列，不以模拟输出或离线通过代替。
