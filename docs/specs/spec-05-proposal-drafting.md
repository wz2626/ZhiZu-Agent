# Spec 05：V3 合同绑定反提案草稿

2026-11-04状态：保留旧草稿接口与测试；新右侧主流程改用[Spec 07](spec-07-quote-analysis.md)，无需审查上下文。本规范不约束新接口。

## 表达风格与唯一动作入口（2026-11-02 本轮功能调整）

草稿请求加性支持 `expression_style: gentle | concise | firm`，省略时为 `gentle`，分别为温和协商、简明正式、坚定明确。仅该枚举影响服务端可信风格指导，不接受自由系统提示。现有响应与模型输出字段不变；目标和回答的2000字总预算不包含风格。幂等指纹包含规范化后的风格，省略与显式默认值相同，同号不同风格409，重试恢复原快照中的风格。

风格归属条款记录。切换风格不自动调用模型或改写最终消息，递增现有本地修订、使旧在途结果失去接纳资格；保留草稿和回答，并提示更新后生效。生成结果记录其请求风格，旧稿仍可人工采用。风格只改变措辞与组织，不授权改变事实、金额、期限、立场、可接受范围、法律边界或捏造让步/承诺；坚定明确不等于威胁或确定法律结论。真实语气与事实保持仍需模型样本核验，不由格式检查冒充语义保证。

表达助手仅有一个稳定的生成/更新/同号重试按钮，置于目标、风格及所有补充信息之后。字数与不可用原因紧邻该按钮，保留aria-describedby；无新问题或仅有历史回答时同样可更新。补充问题与旧回答的ID、所有权、预算、隐私预览及独立演练边界不变。

## V4 后端单飞与恢复（2026-10-31 授权）

proposal 仅要求 X-Interaction-Version:4，不要求练习头。保留正文 draft_request_id，不新增 Idempotency-Key/goal_revision/claim_flags。同上下文+请求编号唯一，指纹是比较值而不是键的一部分；同键异文409。短锁内检查归属/问题及额度并预留操作，锁外云调用，同号有界等待同一操作，绝不重复调用。在途与已发布完成操作均计入每上下文64次预算；abort 退出后释放在途名额，移入独立防重入身份集合（随上下文结束释放，单上下文最多6400个）；达到该身份上限返回暂时容量不足，不无界积累。

问题账本独立于响应条目，仍归上下文和条款；questions 与 question_items 的顺序、文字和数量必须相等。上下文保持30分钟固定 TTL，新操作需存活上下文；已受理操作持有快照，过期不影响 deadline 内完成。回执独立于上下文保留至受理后3600秒，恢复先查回执再查上下文。操作 deadline 默认90秒；只按服务端 deadline 判定迟到，HTTP 超时不作废操作。超期工作不可发布，保留可识别终止回执直至恢复窗结束；实际线程退出后才释放执行容量。超时编号不重新执行，但不占已发布/在途的64名额。全局回执容量6400，满时拒绝新操作而不驱逐在途或恢复期内结果。

云并发4、排队最多4、排队等待最多2秒；不足返回503+Retry-After，不能缓存成 needs_review。传输异常直接受控结束，不触发模型自动重试；确定 needs_review 保持可重放。使用短临界区发布完整校验后的响应及问题；客户端/HTTP 生命周期不关闭仍在运行的任务客户端。

## V4.0 结构化补充增补（2026-10-30 授权）

本节覆盖网页1000字及仅四字段的旧约定。保留旧questions:list[str]和旧请求兼容，响应加question_items:[{question_id,text}]；ID由服务端对通过校验的请求和题序生成，缓存回放稳定，新生成的问题获得新ID，不凭问题文本猜测跨代身份。请求增加answers:[{question_id,text}]（默认空，最多16项，每项1～1000字，不重复ID），仅接受同一上下文同一条款历史成功草稿签发的问题；不存在或跨条款问题返回受控422，先于云调用。总预算为goal_text字符数+所有answer.text字符数<=2000，网页与服务端统一，界面持续显示剩余预算，不截断内容。问题标题不重复拼入goal_text；模型获得服务端核验的问题与脱敏回答。900字目标+3条200字回答必须可生成。

旧回答按question_id持续保留为补充事实，新问题独立列出；新生成不自动迁移或覆盖旧回答，同一ID仅有一份当前回答。新生成失败保留旧参考和回答。幂等指纹含排序后的question_id/脱敏回答与目标；同号不同回答409。成功响应为问题生成ID，失败question_items为空；模型仍只输出原三字段，无需让模型管理ID。

生成动作确认当前目标与回答快照，号码本地处理，姓名详细地址人工检查；云端处理标签常驻草稿区。草稿请求不依赖任何谈判tx。保持Critic有界重写、未通过草稿不公开、正式练习状态零修改。V4隐私预览遵循Spec02。

2026-10-25 开发者授权：新增独立、按需生成的协商表达能力。它使用通过审查的上下文帮助组织消息，不改变固定策略房东、计分公式、正式确认条件或五轮上限。离线工程验证与真实模型表达质量分别验收。

## 1. 上下文与输入

详细审查成功时创建 `review_context_id`，绑定不可变的脱敏合同、已通过审查的条款与本次引用的权威法条。服务以有锁、具TTL/容量上限的内存存储保存；标识随机，视为本地应用持有者能力，不作为账号身份验证。重启/过期/淘汰后不能用于新生成请求。验证上下文和条款归属先于任何云客户端初始化，不接受浏览器上传的“已核验”证据。请求获取不可变上下文后不受中途淘汰破坏。

默认上下文30分钟有效、最多100份，容量满时淘汰最久未使用且未pin项；每份上下文的在途与已发布草稿合计最多64个，重复请求不新增记录，abort未发布的编号移入独立防重入集合。失效返回410，新请求条款不归属返回404，同编号内容冲突优先返回409，64名额上限返回429并要求重新审查；429不是暂时服务繁忙。全部上下文被pin或全局回执容量不足返回503，不伪装成图质检失败。

`POST /api/review/proposal` 仅接收严格字段：`review_context_id`、`clause_id`、`goal_text`、`draft_request_id`。标识禁止敏感号码，目标非空且有长度上限；额外字段、非法标识与长度返回受控422，不回显原始输入。客户端请求结构不含谈判提交入口的 `session_id/user_input/request_id` 三字段签名，保留 OpenAPI 唯一发现。

API目标说明为1～2000字，网页输入区上限1000字；生成消息为1～2000字，问题最多8项、每项1～300字。所有文本不能纯空白。模型JSON总长不超过32000字符，重复键、非法常量及深度嵌套安全拒绝。

前端生成前对目标说明做号码遮蔽并展示人工隐私确认；后端在缓存、模型调用和任何公共输出前再次遮蔽。姓名、地址等自由文本仍由用户人工检查。用户说明作为其陈述与目标，不当作房东已确认事实。

## 2. 生成与校验

复用现有聊天模型配置与超时，不新增依赖。上下文提供条款、审查建议与已核验法条；模型只输出 `proposed_message`、`evidence_ids`、`questions`。引用必须属于所选条款的可信证据，不能凭记忆补法条；无证据时只组织诉求/澄清表达并提示依据边界。不得补写个人信息、假造对方已接受条件或给出谈判胜率。

确定性校验检查严格JSON、字段与长度、引用归属和重复、号码脱敏。校验失败最多两次重写、总生成三次；调用异常/超时直接受控失败。格式/引用通过不等于法律语义全面通过；真实质量需另行评估。失败公共响应不含坏草稿、原始异常或任意模型输出。

## 3. 响应与独立幂等

公共响应：三个关联标识 `review_context_id/clause_id/draft_request_id`，`status=success/needs_review`、`proposed_message`、`evidence_ids`、`questions`、`failure_code/reason/errors`、`retry_count`、`trace_label=本次执行回放`、`trace`、`replayed`。失败消息和引用/问题为空，返回受控原因；成功无终止错误。

草稿请求具有独立有界缓存和单飞占位。同编号、同上下文/条款/脱敏目标重放相同结果且不再次调用模型；同编号不同内容409。业务失败可缓存；重新生成需新编号。上下文失效和格式拒绝不调用模型。输入上下文失效不删除已受理操作恢复窗口内的回执；回执独立有界、不创建长期历史。它不读写谈判正式快照、不消耗协商轮次。

Trace 只记录实际发生的 context/configuration/drafting/critic/retry 等事件，序号连续、耗时实测、反馈受控，不包含上下文ID、目标、草稿、异常或隐藏思维。前端完整响应后回放，来源为“反提案生成”，不与其他请求拼接；等待期间只显示真实等待计时。

## 4. 前端接纳与采用（2026-10-29 统一工作区修订）

目标、参考草稿与待补问题归属本地分析版本+条款。请求额外记录目标修订与生成代次，接纳核对上下文、条款、请求及该记录修订，不依赖当前屏幕选中项。切换条款可接收原条款有效结果；修改目标使旧在途结果失效，但已成功生成的旧稿与问题保留为“修改前的参考草稿”。生成失败不删除旧参考。上下文过期仅阻止新生成，不自动重新分析或发送。

生成入口位于右栏沟通任务内。所有响应只进入预览，不自动填入、发送、滚动或聚焦。用户可明确采用参考草稿；已有消息需要确认替换；采用后撤销当前练习消息的隐私确认。目标确认随目标修订保存，消息确认随练习消息修订保存；单Composer切换记录不算编辑。

草稿不拥有唯一协商session，不修改任何正式练习状态或消耗轮次。传输失败保留原草稿请求编号，目标修改或确定业务失败后的重新生成用新编号。旧响应不能覆盖更新目标，不能污染其他条款。无可用上下文仍可手写消息与进行固定剧本练习。

## 5. 验收

离线测试覆盖有效草稿、空证据、未配置、超时、恶意/格式输出、PII、伪造引用、两次重写成功/三次失败、上下文过期/淘汰/条款归属、并发同编号、冲突和缓存重放。前端验证隐私门禁、已有内容替换确认、迟到响应隔离、单Composer、正式状态/轮次零变化与唯一谈判入口。真实模型效果单列，不以模拟输出或离线通过代替。
