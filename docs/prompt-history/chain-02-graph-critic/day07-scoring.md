## 实现演进摘要

以下为实际开发过程摘要，不是逐字重建的代码回复。

1. 保留默认房东的“暂未确认任何条件”行为，不从租客诉求提取确认金额。新增可注入离线响应器，仅从房东完整明确确认模板提取 `deposit_refund`；否定、条件、转述、待审批及重复/冲突金额不会被当作接受。响应器获得深拷贝，不能污染图状态。
2. 新增纯 Python `scoring.py`，按原始进度加权后统一舍入，使用 `Fraction` 防止浮点累计误差或极大权重溢出。目标等于起点、缺失项、禁用项、无效权重不参与归一化；无适用项为 `None`。默认押金规则为起点 0、目标 2000、权重 1，另设演练允许区间 0～2000。
3. 扩展状态以保存可信规则、候选引用、本次可信证据集合、已确认引用、`candidate_score` 和规则解释。沿用原有 `trial_score` 名称保存正式当前分数，避免把未校验试算直接作为正式成绩。
4. 在房东与 Critic 之间增加规则试算节点。Critic 检查候选结构、明确确认、金额与回复一致性、数值有效性、配置底线；兼容 Day 6 的明确非数值安排，但不对这些安排计分。
5. 证据校验拒绝同轮重复、越界、不属于本次可信集合及未出现在房东回复中的引用。可信集合由服务调用方提供，默认空；跨轮确认引用去重保存，法条数不参与算分。此处未实现法条实质支持的通用语义审查。
6. Critic 全部通过后根据合并确认状态再次重算，统一输出条件、引用、分数、解释、历史和新轮次；服务在既有单会话锁内替换深拷贝快照。失败仅保留工作状态中的候选信息，不修改正式会话；重试清空候选，最多重写 2 次。重复成功请求继续返回缓存，同金额以新请求再次确认可推进对话轮次，但不增加分数。
7. 在原测试末尾追加边界用例并新增评分测试；首批专项为 108 passed，首次完成的全量为 375 passed。没有修改 Day 1～6 原有测试逻辑和审查模块。

## 真实缺陷：布尔权重在状态往返时被转为数字

首次全量通过后，AI 自查发现规则在纯函数中排除 `True` 权重，但 Pydantic 对图状态字典反序列化时会把该值转换为数字 `1`。实际只读复现的输出摘录为：

```text
bool True
int 1
```

AI 随后向用户说明，可见回复摘录：

> 全量回归已通过 375 项，0 失败、0 跳过。复核时发现一个额外边界：Pydantic 在状态序列化后可能把布尔权重 `True` 转成数字 `1`，使本应排除的权重参与算分。我会修复这个转换问题，补一项回归测试后再给出最终数字。

实际修复为在 Schema 字段验证前重建规则对象，保留原始数值类型，并新增 `test_day07_graph_roundtrip_never_coerces_invalid_weights_into_points`。该测试验证两次确认 1000 时布尔权重始终不参与算分。专项最终为 109 项，全量最终为 376 项，全部通过。

这是真实发现并修复的类型转换问题；没有用户引导的业务报错，已完成的 pytest 也没有断言失败，不补造“用户报错 → 测试失败”的过程。非法候选、重复证据、错误候选分 99 等测试均为故障注入，应与该自然缺陷区分。
