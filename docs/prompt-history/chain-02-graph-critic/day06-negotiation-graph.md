## 实际生成过程

1. 新增 `negotiation.py`：定义必需的七个状态字段，以及角色历史消息、请求标识、输入、角色输出、确认标记、状态和错误列表；可变容器使用独立默认工厂，`round_count` 限定 0–5、`retry_count` 限定 0–2，分数默认为 `None`。
2. 新增 `negotiation_graph.py`：编排 `tenant_coach → landlord → critic`；通过才追加一次完整历史、合并候选条件并增加一轮。入口发现已完成五轮即直接结束，Critic 失败通过条件边进入有界重写，最多三次生成。
3. 首次生成阶段曾在 Critic 与重写节点两处设置重试计数递增；在首次 pytest 执行前已统一由重写节点递增，避免一次重写重复计数。这是生成过程中的自查调整，没有对应的测试失败，也不是用户报告的自然故障。
4. 新增 `negotiation_service.py`：每个会话分别保存状态、锁和成功请求缓存；注册表锁仅保护会话注册。工作状态、正式状态、返回快照与缓存均作深拷贝；图异常或未通过结果不提交正式状态。同一 `request_id` 的成功请求返回原响应，同 ID 换输入被拒绝，请求标识在不同会话独立。
5. 新增 `test_negotiation.py`：通过合成房东与明确确认标记验证嵌套条件隔离；覆盖双会话交替/并发两轮、不同会话同时进入图、同会话八线程上限、防重复提交、返回值防篡改、有界重写和异常不提交。错误标记与图异常均为明确的离线故障注入。
