## 用户意图与约束

在 Day 1～7 后端基础上，按《智租博弈_大体计划_修订版》开始 Day 8：直接保存 `frontend-web/index.html`，用 Vue 3 和 TailwindCSS 实现无构建工具的三栏看板，分别承载脱敏合同、风险与证据、多角色谈判区。分析前必须先在浏览器遮蔽手机号和身份证号，展示预览，由用户确认后才请求后端；风险卡片以 `original_clause` 精确定位脱敏文本，高亮并平滑滚动。

用户要求先核对任务安排，有异议提前说明；过程中多次中断并要求重新扫描完成度、继续完成，随后询问检查耗时。本轮收尾要求在正式 Commit 前本地化外部运行时、归档过程与测试证据、清理临时文件并只读检查 Git，不授权提交。

## 计划和契约核对

- Day 8 的三栏、前置脱敏和原文联动与修订计划一致；真实回放、清单导出及完整三场景联调属于后续安排。当前后端尚无谈判 HTTP 接口，右栏先呈现场景、角色和本地草稿，并明确标注待接入，不伪造谈判成功或分数。
- 总 Spec [Spec 00](../../specs/spec-00-architecture.md) 与合同审查 [Spec 02](../../specs/spec-02-risk-review.md) 的基线均为上述 Day 7 提交；本轮未修改 Spec。前端调用详细审查接口，区分 `success` 与 `needs_review`，失败时不把零条通过结果解释为无风险。
- 修订计划要求固定版本 Vue 资源随仓库保存、尽量减少现场 CDN 依赖。初始用户明确指定 CDN，页面据此使用 Vue `3.5.13` 和 TailwindCSS browser `4.1.13`；本轮用户进一步要求下载运行时并改用本地相对路径，保留单文件业务页面和无构建工具的交付方式。
- 以用户确认的脱敏快照为请求和高亮的共同坐标；姓名、住址等自由文本仍由用户在可编辑预览中检查处理。后端云调用前二次脱敏的责任不由前端替代。

## 代码生成、继续执行与修正

实现包含响应式三栏布局、输入与可编辑脱敏预览、确认门禁、提交快照、风险和证据卡片，以及右栏场景、角色和本地草稿。预览编辑会撤销确认；提交前再次正则遮蔽，若文本发生变化则返回确认流程。合同和结果通过文本插值呈现，不以 `v-html` 注入输入内容。

点击卡片按 `original_clause` 在脱敏快照中查找精确子串，分段生成高亮；重复原句可切换出现位置，并在渲染后调用 `scrollIntoView`。不存在精确匹配时显示提示，不猜测偏移。页面未实现持久化合同、API Key 输入或实时流式推理展示。

用户多次中断后，先检查现存文件再继续，保留已完成工作。整页写入第一次试图在同一补丁中对 `index.html` 同时执行 Delete 与 Add，被工具以 `multiple operations target` 拒绝；随后程序化生成 Update File 补丁并成功落盘。

浏览器验证脚本经历两次自身修正后重跑：第一次把子元素内容宽度与带 padding 的父元素完整宽度相比较，导致 Tailwind 加载等待条件不成立，改为检查 `.topbar > a` 的 computed `display` 是否为 `flex`；第二次读取 Vue 生产版内部 `__vue_app__._instance.proxy` 时实例为 null，改为点击页面可见按钮完成交互。两次均修正验证脚本，未为适配检查而改动产品代码；这些问题不记为产品自然缺陷，也不冒充云端模型缺陷。完整错误输出和逐次命令仍需随原始执行记录补齐。

主要 Vue 状态为左栏 `rawText`、`previewText`、`submittedText`；隐私流程 `phase`、`privacyConfirmed`、`maskCounts`；中栏 `results`、`selectedClauseId`、`activeMatch`；右栏 `negotiation`。健康检查单独管理，不代表真实云端审查已成功。
