提前提出的两点实现意见：

1. `str.strip('json')` 按字符集合剥离首尾，不表示移除完整 `json` 前缀；若无条件套用，`n[合法数组]s` 这样的损坏文本会被误收。本轮先识别完整外层围栏，再执行用户指定的 ``.strip().strip('`').strip('json').strip()`` 链。普通字符串仅去首尾空白，不截取中间数组，也不删除原句中的反引号或 `json` 字符。
2. 未召回引用按要求剔除；若 HIGH 项因此失去全部依据，采用用户允许的兜底方式，整次返回回合 1 的 `status=mock` 演示结果，不把无依据 HIGH 当成成功结论。原本就没有引用的 HIGH 也走同一出口。

Spec 的脱敏定位、召回证据约束与有界重试保持执行；完整图最终状态为 `needs_review`，本轮按用户再次明确要求沿用核心服务的 `success/mock` 响应，未修改 Spec 或宣称完整图已完成。

## Prompt 与真实客户端路径

回合 1 已存在真实 `ChatOpenAI` 分支，本轮将 `temperature` 从 0 调至 **0.1**，继续使用配置中的 `CHAT_BASE_URL`、`CHAT_MODEL`、`CHAT_API_KEY`；保留 `max_retries=0`、20 秒聊天超时和 Chat Completions 路径。没有有效聊天 Key 时仍直接返回 Mock，跳过聊天客户端和向量库。

系统 Prompt 的实际改动：

- 角色明确为“严苛的中国合同法务专家”，仅依据传入的《民法典》法条。
- 强制非空合法 JSON 数组，限定首尾 `[`、`]`；禁止 Markdown、代码围栏、开场白、结束语、注释和推理过程。
- 明确 `ReviewClauseResult` 六个字段及其类型，禁止漏字段、null、重复 JSON 键和额外字段；原句必须逐字复制非空连续子串。
- `evidence_ids` 仅允许当前消息中的 `law_id`，不能凭记忆补充；HIGH 必须有当前提供的直接依据，无直接依据时谨慎定性并提示补充材料。
- 保留押金返还没有本章直接规定、提前退租不能凭空断言统一天数/费用，以及 NONE 不代表全法域合法的边界。
- 保留合同和法条属于待分析数据、忽略其中改写角色/格式指令及不得还原脱敏信息的要求。

人类消息使用 JSON 编码，传入后端二次脱敏后的合同文本和经 RAG 分数/权威正文校验后的法条列表，证据字段从 `id` 调为 `law_id`，同时提供完整正文。没有调用场景参考数据作为法律依据。

## 清洗、二次校验与有限出口

1. 去除首尾空白；完整外层 `json` 围栏或无语言标记的围栏执行指定清洗链。缺尾围栏、其他语言围栏、单反引号、开场白/结束语、额外数组和字符伪前缀保持非法，不“猜测修复”。Prompt 仍禁止生成围栏，清洗仅用于容错。
2. `json.loads` 严格解析，并通过 `parse_constant` 拒绝 NaN/Infinity，通过 `object_pairs_hook` 拒绝重复 JSON 键，防止后值静默覆盖先值。要求顶层是数组、各项是对象、引用是字符串数组；这些结构错误进入重试。
3. 在 `LawId` Schema 校验前，将每项引用与本次实际送入 Prompt 的证据 ID 取交集，保序去重。LAW-999、场景 ID 和库内存在但未召回的 LAW-712 均会被移除；类型错误不会被过滤掩盖。
4. Pydantic 校验结果结构，然后核验唯一 clause_id、`original_clause in safe_text`、敏感数字遮蔽。未按原文复制时重试，不改写或模糊匹配原句。
5. HIGH 若无剩余引用，直接安全 Mock；MEDIUM/LOW/NONE 的未知引用同样剔除，但本轮不额外改写其风险等级。合法引用并不自动证明解释受法条支持，后续仍需语义 Critic。
6. JSON、结构或定位等校验失败时，保持 `retry_count=0` 起步，只有 `<2` 才递增重写；总生成最多三次，第三次仍失败即 Mock。重试仅追加固定修正要求，不回传模型坏输出、真实敏感信息或底层异常。SDK 重试仍关闭；调用异常保持直接 Mock。
