## 责任与真实性

- 开发者使用工具支持的功能导出完整原始对话；不支持导出时，用连续截图或录屏保留用户提问、AI 可见回复及用户引导修复过程。
- 编码 Agent 根据收到的实际材料整理文件与索引，不改写原始记录。审查 Agent 仍遵守只读职责。
- 未收到原始记录时标注“待归档”或“待补原始记录”，不得宣称已有完整链，不得事后编造对话。
- 摘要只用于检索。只保存 Prompt、成功结果截图或最终回复，不能代表完整链；无需记录模型隐藏思维。
- 自然缺陷据实记录；人工构造的问题必须标为“故障注入”，不能冒充实际发生的缺陷。

## 文件命名

采用 `顺序号-主题-工具.原生扩展名`，如 `01-initial-codex.json`、`02-review-kimi.md`、`03-repair-codex.html`。示例不表示任何工具必然支持这些导出格式；以实际导出格式为准，不为统一格式改写原件。

顺序号表示归档快照顺序。一份导出可以包含多轮对话，一次功能迭代可以关联多个快照。截图使用 `03-shot-01.png`，录屏使用 `03-recording-01.mp4`。跨工具交互按实际发生顺序连接；日期、实际模型及 Spec 基线版本放在索引中，模型不明时写“未确认”。同一聊天覆盖多次迭代时，可通过消息位置或录屏时间点定位。

## 各链 README 标准结构

初始索引只需范围、归档状态和空表。收到原始记录后，再据实补充以下结构：

```markdown
# 链名称

## 范围与归档状态
本链范围；完整 / 待补原始记录。

## 迭代索引
| 迭代 | 时间（北京时间） | 工具/模型 | 意图与结果 | 原始记录 | 测试证据 | 关联代码 Commit |
| --- | --- | --- | --- | --- | --- | --- |

## 关键迭代
### I01：实际迭代主题
- Spec 路径及基线版本（对应提交或文件版本）
- 用户目标与约束
- 实际缺陷或明确标注的故障注入
- 用户引导修复的过程
- 复测结果与 docs/test-results/ 下的证据链接
- 消息位置、截图编号或录屏时间点

## 待补材料
仅列实际缺失项。
```

索引中的文件与测试结果使用相对链接。未运行、失败或跳过须如实标明；不能用模型自评代替实际测试证据。

## Commit 核实与回填

开发者手动执行所有 Git 写操作。提交前关联代码 Commit 写“待提交”；提交后 Agent 可用只读 `git --no-optional-locks log`、`show` 或 `diff` 核对实际变更，再填写真实哈希。索引记录关联的代码提交，不要求包含索引文件自身所在提交的哈希。新增索引可随后续有实际内容的文档提交保存，不为回填制造无意义提交。

## 敏感信息与原件保护

录入和导出前检查密钥、手机号、身份证号、姓名与住址等个人信息，不将其提交到公开仓库。若原始材料含敏感信息，由开发者保管原件并提供脱敏副本；仓库中明确标注“脱敏副本”及处理范围。Agent 不静默修改原件或将脱敏副本无说明地称为原件；脱敏不得改写交互含义或补造缺失内容。
