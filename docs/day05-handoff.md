## 3 Day 5 工作顺序

### 3.1 首次真实模型小规模验证

1. 与用户确认实际使用的聊天模型、向量模型及服务地址，指导在本地 `.env` 配置凭据。保留已有配置，检查时不输出 Key，也不要求将 Key 发到聊天里。同一服务商支持时两类能力可共用一个 Key；不要默认必须申请两把。
2. 使用独立的云端向量目录，选定同一向量模型、标识和维度用于入库与检索。保留 Mock 库供离线测试，不删除或混用。当前代码默认云端模型配置只是默认值，不等于已调用成功。
3. 首次及重复入库都核实总数32，验证五类检索问题，回查 ID、正文与来源。再用一至两份脱敏合成合同测试真实审查，核对状态、原句、引用、风险计数及初步内容合理性。
4. 真实模式入库显式使用 `--mode cloud`，避免 `auto` 因缺 Key 静默使用 Mock。示例：将本地 `CHROMA_PATH` 配置为独立目录（例如 `./.runtime/chroma_cloud`）后，在仓库根目录执行 `.\.venv\Scripts\python.exe scripts/init_kb.py --mode cloud --verify-queries`。API 必须读取同一路径；已有进程环境变量优先于 `.env`，修改配置后重新启动服务。该命令是待执行示例，本轮没有运行。
5. HTTP 200、`env_configured=true` 或 `status=mock` 不算真实审查通过。记录实际调用模式、模型名称、命令、输出、耗时及失败原因；失败回退不能作为真实成功证据，结构校验通过也不能等同于法律语义完全正确。
